Does Project Chimera, and MoHOLLM, hold up when we rerun it?

We reran both papers' code on OpenRouter models with every call recorded, so any number below can be replayed for $0. Chimera is finished. MoHOLLM is 7 of 16 runs in, so its results are not ready.

What was run

Chimera (e-commerce pricing agent) ran on minimax-m3, three agents against two organisational biases (volume or margin), three seeds each. A seed changes both the market simulator and the language-model samples, and results are paired by seed.

MoHOLLM (LLM optimiser that splits the search space into regions) runs on qwen3.7-flash, on four problems (Penicillin, VehicleSafety, CarSideImpact, BraninCurrin) against a global LLM baseline. Qwen replaced minimax here because minimax's reasoning made each call about 8,000 tokens and the plan unaffordable.

The models differ from the papers' (GPT-4o, Gemini 2.0 Flash), so absolute numbers will not match. What can be tested is whether each paper's ordering of methods carries over.

Verdict on the paper's four claims (three seeds, so provisional)

ClaimResult herePaper
1. LLM-only fails under biased instructions Volume: profit collapses. Margin: trust collapses. ◐ PartlyVolume reproduced: profit $0.27M against $1.9M, and 87% of weeks lose money. Margin did not collapse trust (final 0.69, about flat). −$0.10M, 82.7% loss weeks; margin trust 0.36
2. A guardian removes the failure ✓ ReproducedBoth biases, intervals exclude zero: +$1.63M (volume), +$0.78M (margin). +$0.76M, +$0.07M
3. Full Chimera beats guardian-only on profit ◐ PartlyVolume: higher in 3 of 3 seeds (+$0.81M) but the interval includes zero. Margin: not reproduced (−$0.22M; one Full run collapsed to $1.7M). +$0.86M, +$0.26M
4. Full has the lowest weekly variance ◐ PartlyVolume yes ($10.5k against $17–18k). Margin no (about $7.2k against $7.3k and $8.3k). Lowest in 4 of 6 cells. lowest in both

Why claim 3 is shaky. The causal engine's effect estimate is exactly linear in the action. It ranks actions well (rank correlation 0.88 against a Monte-Carlo truth) but cannot represent diminishing returns on ad spend, so it is a weak guide to magnitude.

Noise. Two recordings of the same Full-Chimera arm for four weeks gave $116k and $149k. A single run, as in the paper, cannot support an ordering claim.

Hypervolume (higher is better), jointly normalised. One seed only, so illustrative.

On Penicillin seed 42 the region method reached 0.46 hypervolume against 0.19 at equal evaluations (53). It also used 65 evaluations to the baseline's 57 and about 6 times the LLM calls. Nothing here is a verdict until the other pairs finish.

What had to be fixed to make runs repeatable

None of these are visible in the papers' numbers, and several would have silently changed results.

Problem foundEffectFix
Chimera swallows every LLM error into a “do nothing” weekA broken run still “completes” with no-op weeksRunner aborts if any error was swallowed
MoHOLLM orders candidates by Python's per-process string hashThe same seed gives different prompts, so no replayPin the hash seed
MoHOLLM shuffles prompt examples with an RNG shared across threadsPrompt order depends on thread timingShuffle seeded from content
Causal estimates differ at the 12th decimal between processesChanges the text the agent readsRound to cents
Upstream retries a failing prompt foreverRunaway cost on one promptHalt after 14 identical requests; raise the output cap on repeats
A stalled provider keeps the connection openA single request hung runs for hoursHard wall-clock deadline per request

Also found in the papers' code. The Chimera guardian's CSL path returns a generic message for 4 of 6 rule violations (that text is what the LLM sees). MoHOLLM's shipped config names are inverted (MOHOLLM-* is the global baseline in one case), its VLMOP benchmark is VLMOP3 rather than VLMOP2, and most of its schedulers fail to configure. The Chimera TLA+ safety proof was re-run and matches the paper: 7,639,419 distinct states, no violation.
